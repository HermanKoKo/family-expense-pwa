# Family Expense PWA - Project Constitution

## Project Context (專案背景與技術選型)

### 專案背景
Family Expense PWA 是一個專為「柯與心儀」設計的專屬記帳應用程式，旨在幫助夫妻雙方輕鬆管理家庭開支、收入和財務狀況。這是一個 Progressive Web App，提供原生應用般的使用體驗，同時支持離線操作和雲端同步功能。

### 技術選型
- **前端框架**: Vue 3 (Composition API) - 選擇 Vue 3 是因為其響應式系統、組件化架構和良好的生態系統
- **狀態管理**: Pinia - Vue 官方推薦的狀態管理庫，比 Vuex 更簡潔和直觀
- **路由管理**: Vue Router 4 - 提供強大的路由功能和導航控制
- **構建工具**: Vite - 快速的開發服務器和優化的生產構建
- **樣式系統**: Tailwind CSS - 實用程序優先的 CSS 框架，提高開發效率
- **本地存儲**: IndexedDB (via idb-keyval) - 支持大量數據存儲和離線功能
- **雲端同步**: Google Sheets API - 簡單易用的雲端存儲解決方案
- **PWA 支持**: vite-plugin-pwa - 提供安裝提示、離線緩存和原生應用體驗
- **UI 組件**: Heroicons - 美觀的 SVG 圖標庫
- **繪圖效果**: Rough.js - 手繪風格的 UI 元素

### 專案結構
```
src/
├── assets/          # 靜態資源
├── components/      # 可重用 UI 組件
├── services/        # 數據訪問和業務邏輯
├── stores/          # 全局狀態管理
├── views/           # 頁面級組件
├── router/          # 路由配置
├── App.vue          # 主應用組件
└── main.js          # 入口文件
```

## Style Guides (代碼風格規範)

### 代碼組織
1. **組件結構**: 使用 `<script setup>` 語法糖，遵循 Composition API 模式
2. **文件組織**: 按功能模塊劃分目錄，保持清晰的責任分離
3. **組件大小**: 保持組件小而專注，單個組件不超過 300 行代碼
4. **導入順序**:
   - Vue 核心功能
   - 第三方庫
   - 本地組件/服務
   - 靜態資源

### 命名規範
1. **組件命名**: PascalCase (e.g., `ToastNotification.vue`, `RoughWaterLevel.vue`)
2. **函數和變量**: camelCase (e.g., `addLog`, `expenseCategories`, `currentUser`)
3. **常量**: UPPER_CASE (e.g., `STORES.LOGS`)
4. **服務類**: PascalCase (e.g., `DBService`, `APIService`, `SyncService`)
5. **路由命名**: kebab-case (e.g., `editor`, `dashboard`, `history`)
6. **中英文混用**: 允許中文用於用戶界面文本和註釋，技術術語使用英文

### 代碼風格
1. **縮進**: 2 個空格
2. **引號**: 單引號優先，模板字符串使用反引號
3. **分號**: 可選，但保持一致
4. **註釋**:
   - 中文註釋，簡潔明了
   - 重要邏輯或複雜算法必須有註釋
   - 公開 API 和函數參數需要文檔註釋
5. **Tailwind CSS**: 直接在模板中使用實用程序類，避免自定義 CSS

### Vue 特定規範
1. **組件屬性**: 使用 `defineProps` 和 `defineEmits`
2. **響應式數據**: 使用 `ref` 和 `computed` 而不是 `reactive`
3. **生命週期鉤子**: 使用 `onMounted`, `onUpdated` 等 Composition API 鉤子
4. **模板語法**: 使用 `v-if`/`v-for` 而不是 JavaScript 邏輯
5. **事件處理**: 使用 `@click` 而不是 `v-on:click`

## Rules (開發原則)

### 代碼質量
1. **保持簡潔**: 避免過度工程化，保持代碼簡單直接
2. **單一責任**: 每個函數/組件只做一件事，並做好
3. **錯誤處理**: 所有異步操作必須有錯誤處理和用戶反饋
4. **性能考慮**: 避免不必要的計算屬性和監聽器
5. **離線優先**: 所有功能必須在離線狀態下正常工作

### 同步與數據管理
1. **防抖同步**: 使用防抖技術減少 API 請求次數
2. **隊列管理**: 所有待同步數據必須進入隊列，避免直接寫入
3. **衝突解決**: 使用 Last-Write-Wins 策略解決同步衝突
4. **數據一致性**: 確保本地狀態和 IndexedDB 保持一致
5. **用戶反饋**: 同步操作必須有明確的用戶反饋（成功/失敗）

### 用戶體驗
1. **移動優先**: 設計和開發必須優先考慮移動設備
2. **響應式設計**: 所有 UI 元素必須適應不同屏幕尺寸
3. **可訪問性**: 確保所有功能對屏幕閱讀器友好
4. **性能**: 保持應用快速響應，避免阻塞主線程
5. **離線體驗**: 提供明確的離線狀態指示和同步狀態

### 國際化與本地化
1. **語言**: 主要使用繁體中文，技術術語使用英文
2. **日期格式**: 使用 `YYYY/MM/DD` 格式
3. **貨幣**: 使用新台幣 (NTD) 並顯示適當符號
4. **時間**: 使用 24 小時制

### 安全性
1. **數據驗證**: 所有用戶輸入必須驗證和清理
2. **API 安全**: 不要在客戶端存儲敏感信息
3. **錯誤報告**: 生產環境錯誤應記錄但不暴露敏感信息
4. **數據備份**: 提供數據導出功能以防意外數據丟失

### 文檔與註釋
1. **註釋語言**: 使用繁體中文，簡潔明了
2. **文檔完整性**: 所有公開 API 和組件屬性必須有文檔
3. **代碼自描述**: 優先使用清晰的命名而不是過多註釋
4. **TODO 注釋**: 使用 `// TODO:` 標記待辦事項

### 測試
1. **單元測試**: 核心業務邏輯必須有單元測試
2. **集成測試**: 重要用戶流程必須有集成測試
3. **端到端測試**: 關鍵功能必須有 E2E 測試
4. **測試覆蓋率**: 目標 80% 以上代碼覆蓋率

### 版本控制
1. **提交信息**: 使用中文，格式為 `[類型] 描述` (e.g., `[feat] 新增類別管理功能`)
2. **分支策略**: 使用功能分支工作流
3. **提交頻率**: 小而頻繁的提交，避免巨大提交
4. **代碼審查**: 所有代碼必須經過審查才能合併
